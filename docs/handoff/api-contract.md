# ShelfSense API Contract Verification

> Verified against NestJS backend endpoints running at `http://localhost:4000/api/v1`.

## 1. Response Envelope Format
All successful responses from the NestJS backend are wrapped in the standard `TransformInterceptor` envelope:
```json
{
  "statusCode": 200,
  "message": "Data retrieved successfully",
  "data": { ... } | [ ... ],
  "timestamp": "2026-10-17T09:44:00.000Z"
}
```
*Note: Decimal fields from Prisma are automatically serialized to JavaScript floating point numbers by the interceptor.*

## 2. Error Response Envelope Format
Errors generated by `HttpExceptionFilter` follow the standard shape:
```json
{
  "statusCode": 400,
  "message": "Validation failed" | ["email must be an email", "password should not be empty"],
  "error": "Bad Request",
  "timestamp": "2026-10-17T09:44:00.000Z"
}
```

## 4. Session & Proxy Strategy
- The frontend client never touches or stores the raw JWT in `localStorage` or `sessionStorage`.
- `web/src/app/api/auth/login/route.ts` proxies credentials to `http://localhost:4000/api/v1/auth/login` and sets `accessToken` as an `httpOnly` cookie.
- `web/src/app/api/proxy/[...path]/route.ts` forwards API calls to `http://localhost:4000/api/v1/[...path]`, attaching `Authorization: Bearer <cookie_token>`.
